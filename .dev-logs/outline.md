# Agent Team 完整设计大纲

## 一、定位

一个独立的 OpenClaw Skill（名为 `agent-team`），通过 `coding-agent` 能力拉起多个 AI coding agent 组成虚拟开发团队，按软件工程流程协作完成项目。

## 二、安装方式

独立技能包，不与 OpenClaw 源码耦合。通过以下任一方式加载：

- `skills.load.extraDirs` 指向技能包目录
- Symlink 到 `~/.openclaw/skills/`

## 三、角色设计

### v1 核心角色

| 角色          | 实现方式                      | 推荐模型级别 | 会话模式           | 核心职责                                                             |
| ------------- | ----------------------------- | ------------ | ------------------ | -------------------------------------------------------------------- |
| **PM**        | OpenClaw 自身（Skill prompt） | 中等         | —                  | 用户沟通、需求澄清、文档输出、进度跟踪、验收交付、复盘               |
| **架构师**    | 独立 Agent                    | 强推理       | 路径 B（会话保持） | 代码库分析、技术方案、数据模型/API 设计、任务拆解、技术风险评估、ADR |
| **Developer** | 独立 Agent（可并行 × N）      | 中等偏上     | 路径 B（会话保持） | 编码实现，按模块/任务分配，默认全栈，可按需分前后端                  |
| **Tester/QA** | 独立 Agent                    | 中等         | A 或 B 视情况      | 测试计划、写测试、跑测试、测试报告、bug 反馈                         |

### v2 扩展角色

| 角色              | 实现方式   | 推荐模型级别 | 会话模式         | 核心职责                       |
| ----------------- | ---------- | ------------ | ---------------- | ------------------------------ |
| **Code Reviewer** | 独立 Agent | 强推理       | 路径 A（一次性） | 代码审查、质量把关、安全检查   |
| **DevOps**        | 独立 Agent | 中等         | 路径 A（一次性） | CI/CD 配置、部署脚本、基础设施 |
| **Tech Writer**   | 独立 Agent | 中等偏下     | 路径 A（一次性） | API 文档、README、用户指南     |

## 四、Agent 支持

| Agent       | 指定模型            | 会话恢复                        |
| ----------- | ------------------- | ------------------------------- |
| OpenCode    | `-m provider/model` | `--session <id>` / `--continue` |
| Claude Code | `--model name`      | `--resume <id>` / `--continue`  |
| Codex       | `-m model`          | `exec resume <id>`              |

初期统一使用 OpenCode，Agent 类型可配置，后期可按角色指定不同 Agent。

## 五、项目流程

```
① 需求澄清 ──→ ② 方案设计 ──→ ③ 分派开发 ──→ ④ 集成质检 ──→ ⑤ 交付复盘
   (PM)          (架构师)       (Developer×N)   (Tester+       (PM)
                                                 Reviewer)
```

| 阶段       | 执行角色                 | 输入                | 输出                                                  |
| ---------- | ------------------------ | ------------------- | ----------------------------------------------------- |
| ① 需求澄清 | PM                       | 用户需求            | PRD、用户故事、功能规格、交互说明、项目计划           |
| ② 方案设计 | 架构师                   | PM 的文档 + 代码库  | 技术方案、数据模型、API 设计、任务拆解、风险评估、ADR |
| ③ 分派开发 | PM 调度 → Developer 执行 | 任务拆解            | 代码变更、变更日志                                    |
| ④ 集成质检 | Tester（+ Reviewer）     | 代码变更 + 需求文档 | 测试报告、review 意见 → 问题打回 Developer            |
| ⑤ 交付复盘 | PM                       | 全部产出            | 验收确认、部署文档、复盘记录                          |

## 六、文档体系

PM 根据项目规模自动裁剪文档集（不是每个项目都需要全部文档）。

### 裁剪依据

| 判断维度              | 小项目   | 中项目  | 大项目 |
| --------------------- | -------- | ------- | ------ |
| 功能点数量            | 1-3 个   | 4-10 个 | 10+    |
| 是否有前后端分离      | 否       | 可能    | 是     |
| 是否有数据持久化      | 无或简单 | 有      | 复杂   |
| 是否有外部集成        | 无       | 少量    | 多个   |
| 预期并行 Developer 数 | 1        | 1-2     | 3+     |

### 文档裁剪规则

| 文档                | 小项目         | 中项目       | 大项目 |
| ------------------- | -------------- | ------------ | ------ |
| PRD（需求文档）     | 必须（可精简） | 必须         | 必须   |
| 用户故事 + 验收标准 | 必须           | 必须         | 必须   |
| 功能规格（FSD）     | 合并到 PRD     | 必须         | 必须   |
| 交互/原型说明       | 不需要         | 有 UI 则需要 | 必须   |
| 项目计划            | 不需要         | 必须         | 必须   |
| 技术方案            | 必须（可精简） | 必须         | 必须   |
| 数据模型设计        | 不需要         | 有 DB 则需要 | 必须   |
| API 设计            | 不需要         | 有接口则需要 | 必须   |
| 任务拆解            | 必须           | 必须         | 必须   |
| 技术风险评估        | 不需要         | 建议         | 必须   |
| 测试计划/报告       | 不需要         | 必须         | 必须   |
| 部署文档            | 不需要         | 按需         | 必须   |
| ADR（架构决策记录） | 不需要         | 按需         | 必须   |
| 复盘记录            | 不需要         | 建议         | 必须   |

## 七、通信机制

| 机制             | 用途                       | 方式                                                  |
| ---------------- | -------------------------- | ----------------------------------------------------- |
| **文件传递**     | 角色间传递文档、方案、报告 | `.agent-team/docs/`、`.agent-team/tasks/`             |
| **Event 通知**   | Agent 完成/出错时通知 PM   | `openclaw system event --text "Done: ..." --mode now` |
| **透传**         | 用户直接与某角色沟通       | `@角色名 消息内容`，PM 原文传递，原文返回             |
| **Session 恢复** | 多轮交互保持上下文         | `--session/--resume` + `.agent-team/sessions/` 管理   |

## 八、流程管理

- Prompt 内置流程定义（阶段、角色、检查点）
- `state.json` 记录当前阶段和状态，防止长会话中迷失
- 每个阶段有明确的入口条件和出口条件

## 九、实现优先级

| 优先级 | 内容                                                        | 状态 |
| ------ | ----------------------------------------------------------- | ---- |
| **P0** | PM 角色 prompt + 项目流程定义 + 文档目录结构 + 文档裁剪规则 | 当前 |
| **P1** | 架构师角色 + 拉起/通信机制                                  | 待定 |
| **P2** | Developer 角色 + 并行任务分派 + 会话保持                    | 待定 |
| **P3** | Tester 角色 + 测试流程                                      | 待定 |
| **P4** | 透传机制（`@角色名`）                                       | 待定 |
| **P5** | v2 扩展角色（Reviewer/DevOps/Tech Writer）                  | 待定 |

> P1 及以后的优先级在 P0 完成后根据实际情况决定——可能优化 PM 角色，也可能推进其他功能。
